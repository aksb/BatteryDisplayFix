# 修改电池百分比显示

由于本人红米K40S手机电池故障，20% 以下会直接关机，但是电池还很耐用舍不得换掉。所以用AI写了个LSPosed模块，干脆把 20% (关机点)当作"0%"，

LSPosed 模块：把状态栏 / 锁屏 显示的电量百分比**文字**，
按你自己填的"关机点"重新计算显示，不改真实电量、不改电量条图形；
另外支持一个可开关的低电量提醒。

```
显示值 = 原始电量 <= x ? 0 : round((原始电量 - x) / (100 - x) * 100)
```

x 是"实际电量关机点"，在 App 设置界面里填，默认 20（结果会夹在 0~100 之间）。

适用场景：电池老化，到某个百分比就会直接关机，所以干脆把这个百分比当作
"0%"，剩余可用区间重新拉伸显示。

## 目标环境

- 只在本人一台红米K40S PixelExperience Office，Android 13测试通过
- 目标进程：`com.android.systemui`
- 目标类：`com.android.systemui.statusbar.policy.BatteryMeterView`
  （或 Android 12+ 重构后的 `com.android.systemui.battery.BatteryMeterView`，
  代码里两个都会尝试）

## 功能

### 1. 电量显示修改（可开关，拨动即生效）

在设置界面填"实际电量关机点 x"，输入框右边有独立的"保存"按钮，填完点一下
立刻生效（不需要连着下面的开关一起保存）。模块自动按公式换算状态栏/锁屏
电量文字。

"状态栏电量显示修改"这个开关只决定"要不要把换算结果显示出来"——换算本身
只要填了 x 就始终在后台计算，不受这个开关影响；关闭后状态栏显示系统原始
电量文字。这个开关拨一下就直接写入配置，不需要额外点保存。

### 2. 低电量提醒（可开关，依赖显示开关）

**必须先打开"状态栏电量显示修改"，"低电量提醒"才能打开**；显示开关关闭时，
提醒开关会灰掉禁用，并且强制摆回"关"（界面上的状态和底层配置一起清成
关闭，不是只灰不改状态）。原因：提醒通知报的是"换算后"的电量，如果显示
开关是关的，状态栏看到的还是系统原始电量，两个数字会对不上。重新打开
显示开关后，提醒开关恢复可点，但默认还是关的，不会自动恢复成之前开着的
状态，需要手动再开一次。

开启后，**换算后**的电量低于 20%、10%、5%、1% 时各提醒一次（普通通知，
可以手动划掉）。规则：

- 判断标准是"当前换算后电量 ≤ 某档位，且这档这一轮还没提醒过"，不是精确
  等于某个数字，避免电量跳档导致漏判。
- 已经提醒过的档位，即使电量在附近小幅抖动，也不会重复弹通知（天然滞回）。
- 充电中不提醒；插上电的那一刻清空所有"已提醒"标记，方便下次拔电重新
  从头计。
- 如果是在电量已经很低的时候才打开这个开关，会一次性补提醒"最接近当前
  电量"的那一档，不会把已经跌过的更高档位也一起补上。
- 通知是以 SystemUI 的身份发出的（借用系统进程权限，不需要额外弹窗申请
  通知权限），所以下拉通知栏看到的应用名会显示成 "System UI"，而不是
  这个 App 自己的名字——这是有意为之，让它看起来更像系统原生提醒。

### 跨进程配置：ContentProvider

App 的设置界面和被 Hook 的 SystemUI 是两个完全独立的进程，普通
SharedPreferences 不能跨进程共享。本模块用 `ConfigProvider`（一个
ContentProvider）做桥接：App 写入配置，Hook 代码里的
`updatePercentText` 每次触发时通过
`ContentResolver.query()` 读取最新配置。这个方案不依赖文件权限，
比 XSharedPreferences 更稳，不用担心 SELinux 权限问题。

## 一、用 GitHub Actions 自动编译 APK

1. 把整个项目 push 到你自己的 GitHub 仓库（仓库根目录要直接是这个文件夹
   里面的内容，`build.gradle`、`settings.gradle`、`app/`、`.github/` 都在
   根目录，不要多套一层）。
2. 进入仓库的 **Actions** 标签页，等待 `Build APK` 这个 workflow 跑完
   （push 会自动触发，也可以在 Actions 页面手动点 `Run workflow`）。
3. 跑完之后，在该次运行的页面下方 **Artifacts** 里下载
   `BatteryDisplayFix-debug-apk`，解压得到 `app-debug.apk`。

首次构建时间大概几分钟，之后有 Gradle 缓存会快一些。

### 发布正式 Release（任何人不登录都能直接下载）

上面第 3 步下载的 Artifact 需要登录 GitHub 账号，而且 90 天后自动过期。
如果想要一个任何人打开链接就能直接下载 apk 的正式发布页，推送一个
`v` 开头的 tag 即可自动触发：

```
git tag v1.0
git push origin v1.0
```

推送后 Actions 里会多跑一个 `release` 任务，跑完在仓库首页右侧
**Releases** 里就能看到 `v1.0`，apk 已经自动附加在里面，任何人访问
仓库链接都能直接下载，不需要登录。以后每次想发新版本，改完代码
先正常 push 到分支，确认没问题后再打一个新 tag（比如 `v1.1`）push
即可。

## 二、安装与启用

1. 把 `app-debug.apk` 传到手机上安装（这是 debug 包，安装时如果提示
   "未知来源" / "解析包出错" 之类，正常允许安装即可，不影响功能）。
2. 打开 **LSPosed Manager** -> 模块列表 -> 找到"电量显示重算"，勾选启用。
3. 在该模块的**作用域**里，勾选 **System UI**（`com.android.systemui`）。
4. 重启手机（或者至少重启 System UI / Soft reboot 让新 hook 生效）。
5. 打开这个 App（桌面图标就是"电量显示重算"），填好关机点、按需打开两个
   开关，点"保存"。

## 三、如果没生效怎么排查

这个模块用的是 AOSP 原生的类名/方法名/字段名，PixelExperience 大概率兼容，
但不排除个别版本有细微差异。排查步骤：

0. **先确认模块真的加载进了 System UI 进程**：LSPosed Manager 里给模块的
   作用域要勾选"System UI"（对应包名 `com.android.systemui`），而不是
   "系统框架"（`system_server`）——这两个是不同进程，勾错了模块根本不会
   在电量相关代码里执行到，也就不会有任何相关日志。
1. 打开 **LSPosed Manager** -> 日志 (Logs)，搜索关键字 `BatteryDisplayFix`。
2. 如果看到 `所有候选类均未命中`，说明 `MainHook.java` 里
   `BATTERY_VIEW_CLASS_CANDIDATES` 数组里列出的几个类路径在这台 ROM 上都
   不存在，需要用 jadx 反编译一下 SystemUI 的 apk，在里面搜索
   `BatteryMeterView` 确认真实类名，再把新路径加进这个数组（不用删旧的，
   多个候选路径可以共存）。
3. 如果看到 `类命中(...)但方法未找到(updatePercentText)`，说明类对了，
   但是这个方法名在这台 ROM 上不一致，需要对照反编译结果修改
   `UPDATE_TEXT_METHOD` 常量。这会导致电量文字没法被修改，**低电量提醒
   也会跟着失效**（提醒逻辑就挂在这个 Hook 点上，没触发到就完全不会执行）。
4. 如果看到 `设置文本失败`，说明类和方法都 hook 上了，但是 `mLevel` 或
   `mBatteryPercentView` 这两个字段名不对，同样需要对照反编译结果，修改
   `LEVEL_FIELD` / `PERCENT_VIEW_FIELD` 常量。这个失败同样会连带低电量
   提醒一起失效（`mLevel` 读不到，后面算换算值、判断提醒档位都执行不到）。
5. 如果日志里完全搜不到 `BatteryDisplayFix` 字样（连"候选类未命中"都
   没有），回到第 0 步重新检查作用域勾选是否生效、是否重启过手机。
6. 低电量提醒完全不弹（但显示修改本身工作正常）：先确认 App 里"状态栏
   电量显示修改"和"低电量提醒"两个开关是否都打开（提醒依赖显示开关，
   见上面"低电量提醒"一节）；再检查是否处于充电状态（充电中按设计不
   提醒）。如果开关都对、也确实没充电还是不弹，翻日志看有没有
   `读取充电状态失败` 或 `低电量提醒处理失败`，一般是权限或系统 API
   返回异常，把日志内容发出来看。

改完常量后，本地不需要装 Android Studio，直接改完 push 上去，
GitHub Actions 会自动重新编译出新的 APK。

## 四、安全性说明

- 本模块不修改任何系统文件，只在 System UI 进程运行期间通过 LSPosed 动态
  挂钩，不生效或者卸载后，系统状态会恢复原样。
- 如果 hook 逻辑触发异常导致 System UI 反复崩溃，可以通过 LSPosed Manager
  关闭本模块作用域，或进入安全模式（Safe Mode）卸载本模块来恢复，不会
  造成系统层面的永久性损坏。
- `ConfigProvider` 是 `exported="true"` 且不设权限校验的，因为这是给自己
  单台设备用的本地工具；如果你打算分享给别人用，上线前应该重新评估权限
  设置（比如加 `android:permission` 限制谁能读写）。

## 五、后续可调整项

- 换算公式本身：改 `MainHook.java` 里的 `calcDisplayLevel` 方法。
- 低电量提醒的四个固定档位（20/10/5/1）：改 `LowBatteryReminder.java` 里
  的 `TIERS` 数组。
- 目前只处理"设置文字"，不动电量条图形（进度条/电池图形），如果以后想
  让图形也跟着换算值变化，需要另外 hook 负责画图的方法（这次按你的习惯
  ——平时关闭电池图标/进度条——特意不处理这部分）。
